# GA4 日次レポートのセットアップ手順

毎朝の日次レポート（Routine）が GA4 Data API からデータを取得できるようにするための、
一度きりの手動セットアップ手順。所要 15〜20 分。

## 全体像と原則

- `scripts/ga4_report.py` が GA4 Data API を **サービスアカウント（SA）** で読み取る。
- **鍵は絶対にリポジトリに置かない**（このリポジトリは公開）。鍵は Claude Code Remote の
  実行環境の**環境変数**にのみ格納する。
- SA には GA4 プロパティの**閲覧者**権限のみを与える（書き込み不可・GCP 側のロールは不要）。

```
[GCP] SAを作成・鍵JSON発行 → [GA4] SAを閲覧者に追加 → [Claude環境] 環境変数に鍵を登録
```

## 1. GCP プロジェクト作成

1. https://console.cloud.google.com を開く
2. プロジェクトセレクタ →「新しいプロジェクト」
3. 名前は任意（例: `agentmgr-analytics`）→ 作成

## 2. Google Analytics Data API の有効化

1. 作成したプロジェクトを選択した状態で「API とサービス」→「ライブラリ」
2. 「Google Analytics Data API」を検索して開き、「有効にする」

## 3. サービスアカウント作成と鍵の発行

1. 「IAM と管理」→「サービス アカウント」→「サービス アカウントを作成」
2. 名前は任意（例: `ga4-daily-report`）→ 作成して続行
3. **ロールの付与はスキップしてよい**（GA4 側の権限だけで動く）→ 完了
4. 作成した SA をクリック →「キー」タブ →「鍵を追加」→「新しい鍵を作成」→ **JSON** → 作成
5. `xxxx.json` がダウンロードされる。**この後の手順が終わったらローカルから削除する**
6. SA のメールアドレス（`ga4-daily-report@....iam.gserviceaccount.com`）を控える

## 4. GA4 プロパティに SA を閲覧者として追加

1. https://analytics.google.com → 対象プロパティ（agentmgr.app / G-W72BR4X8Y6）
2. 「管理」→ プロパティ列の「プロパティのアクセス管理」
3. 「+」→「ユーザーを追加」→ SA のメールアドレスを入力
4. 役割は **閲覧者** → 追加

## 5. カスタムディメンション登録（未実施の場合）

Data API・探索レポートは**登録以降のデータしか**カスタムパラメータを参照できないため、
計測イベントのデプロイ後すぐに実施する。

1. 「管理」→ プロパティ列の「カスタム定義」→「カスタム ディメンションを作成」
2. 以下 5 つを**イベントスコープ**で登録（ディメンション名 = イベントパラメータ名）:
   `cta_location` / `section_id` / `faq_id` / `faq_action` / `hero_view`
3. あわせて「管理」→「イベント」で `cta_click` を**キーイベント**に設定

## 6. GA4 プロパティ ID の確認

「管理」→ プロパティ列の「プロパティ設定」→ 右上の「プロパティ ID」（純数値、例: `123456789`）。
測定 ID（`G-W72BR4X8Y6`）ではない点に注意。

## 7. Claude Code Remote 環境に環境変数を登録

1. 鍵 JSON を 1 行化する（ローカルのターミナルで）:
   ```sh
   jq -c . ~/Downloads/xxxx.json
   ```
   出力された 1 行（`{"type":"service_account",...}`）をコピーする。
2. https://claude.ai/code → Settings → 対象の環境（このリポジトリを実行している環境）→
   Environment variables に以下を追加:
   - `GA4_SA_KEY_JSON` = 手順 1 でコピーした 1 行の JSON 全文
   - `GA4_PROPERTY_ID` = 手順 6 のプロパティ ID
3. 登録できたら、**ローカルにダウンロードした鍵 JSON ファイルを削除**する。

## 8. 動作確認

新しいリモートセッション（環境変数の反映には新セッションが必要）で:

```sh
python3 scripts/ga4_report.py
```

- 成功: `{"generated_at": ..., "reports": {"daily": [...], ...}}` の JSON が出力される
- `環境変数 ... が未設定です` → 手順 7 の登録名・環境を再確認
- `HTTP 403` → 手順 4（GA4 のアクセス権）または手順 2（API 有効化）漏れ
- `HTTP 400 (custom dimension ...)` → 手順 5 のカスタムディメンション未登録
  （登録直後〜24時間程度は反映待ちでエラーになることがある）

※ 計測イベント（`section_view` 等）のデータが実際に貯まるのはデプロイ後。
GA4 のデータ反映には 24〜48 時間かかることがある。

## セキュリティ運用

- **鍵のローテーション**: SA の「キー」タブで新しい鍵を作成 → 環境変数を差し替え →
  古い鍵を削除。年 1 回程度、または漏洩が疑われたら即時。
- **漏洩時**: SA の鍵を削除すれば即座に無効化される。SA 自体を削除してもよい
  （GA4 は閲覧者権限しかないため、被害は「アクセス解析データの閲覧」に限定される）。
- 鍵をリポジトリ・チャット・Issue 等に貼らない。環境変数のみ。
