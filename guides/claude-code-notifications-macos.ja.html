Claude Code の通知を macOS で受け取る
— 完了・確認待ちに気づく方法

更新日: 2026年8月26日

Claude Code は数分間、自律的に作業を続けたあと、静かに止まって待ちます。コマンド実行の許可待ち、 質問への回答待ち、あるいは単に作業完了。その間に Slack やブラウザに切り替えていたら、 何も知らせてくれません。この記事では、macOS で確実に気づくための方法を、1 行の設定から カスタムフックまで順に紹介します。

なぜ気づけないのか

デフォルトでは、待ち状態の Claude Code セッションは完全に無音です。プロンプトは フォーカスされていないターミナルのタブの中に表示されるだけで、Dock も跳ねず、音も鳴りません。 Claude の自律作業時間が長くなるほど、止まった瞬間に自分が別の場所にいる確率は上がります。 結果は誰もが経験するループです — 「念のため」ターミナルを見に行くと Claude は 8 分前から 待っていて、許可を出し、また離れ、また見に行く。

方法 1: ターミナルのネイティブ通知

対応ターミナルを使っているなら、これが最も手軽です。Claude Code は入力待ちになると Ghostty・Kitty・iTerm2 経由で macOS のデスクトップ通知を送れます。

  • Ghostty / Kitty — 追加設定なしで動作します。macOS が通知の許可を求めてきたら許可するだけです。
  • iTerm2 — 事前に有効化が必要です。Settings → Profiles → Terminal で通知（Notification Center alerts）を有効にし、macOS のシステム設定で iTerm2 の通知を許可します。

macOS 標準の Terminal.app にはこの連携がないため、次のベルか hooks を使ってください。

方法 2: ターミナルベル

Claude Code は注意が必要なタイミングでターミナルベルを鳴らせます。 ~/.claude/settings.json に次を設定します。 

{
  "preferredNotifChannel": "terminal_bell"
}

多くのターミナルはベルを視覚化してくれます。Terminal.app はタブにバッジを表示し、iTerm2 は ベルを通知に変換でき、tmux はウィンドウにベルインジケーターを付けます。素朴な仕組みですが、 どの環境でも動き、スクリプトも不要です。

方法 3: hooks — 通知を自由にカスタマイズする

より細かく制御したい場合は、Claude Code の hooks を使います。ライフサイクル イベントに任意のシェルコマンドを紐付けられる仕組みで、通知に関係するのは主に 2 つのイベントです。

  • Notification — Claude が許可や入力を待ち始めたときに発火します。
  • Stop — Claude が応答を終えたとき、つまりタスク完了時に発火します。

次の ~/.claude/settings.json は、どのセッションでも入力待ちになったら macOS 通知を 表示し、タスク完了時にはサウンドを鳴らします。 

{
  "hooks": {
    "Notification": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Claude Code が入力を待っています\" with title \"Claude Code\" sound name \"Glass\"'"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "afplay /System/Library/Sounds/Ping.aiff"
          }
        ]
      }
    ]
  }
}

フックのコマンドは stdin から JSON ペイロードも受け取ります。session_id や cwd、Notification イベントなら message フィールドが 含まれるため、小さなスクリプトを書けば「どのプロジェクトが待っているか」を通知文面に 入れられます。具体例は姉妹記事 「hooks でセッション状態を把握する」を 参照してください。

注意点: macOS の集中モード（Focus）は display notification の バナーも他の通知と同様に抑制します。また、初回の osascript 通知ではターミナル アプリへの通知許可を求められることがあります。短いダミータスクでフックの動作を確認してから 運用に乗せるのがおすすめです。

「一度きりの通知」の限界

ここまでの 3 つの方法はどれも、何かが起きた瞬間に一度だけ鳴るという同じ形をしています。 1 セッションならそれで十分ですが、 複数セッションを並列で走らせると 足りなくなります。

  • バナーは数秒で消え、ベルは鳴った瞬間に終わります。一度逃せば、結局タブの巡回に逆戻りです。
  • 通知は現在の状態を教えてくれません。どのセッションが今もまだ待っていて、どれが対応済みなのか。
  • 必要なアクションの種類も分かりません。ワンキーで済む許可なのか、設計の質問なのか、レビューすべき完了物なのか。

持続する答え: セッションモニター

AgentManager は一度きりの通知を「常に見えるビュー」に置き換える macOS アプリです。フローティングウィンドウに全 Claude Code セッションが状態付きで並びます — 実行中・完了・確認待ち、そして確認待ちの理由まで。どれかが入力を必要とした瞬間に自動で 現れ、全て解消すると引っ込みます。行をクリックすればそのターミナルのペインや IDE の ウィンドウへ直接ジャンプ。ウィンドウを閉じていてもメニューバーのアイコンが待ち数を 表示します。
